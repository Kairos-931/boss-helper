## 目标与用户价值

- 用户目标：浏览搜索结果时，不必先打开公司页再点悬浮球，点击职位条目本身就能完成“这家公司已看过”的记录。
- 目标用户：在电脑 Chrome 上使用 BOSS 直聘搜索结果页的本项目用户。
- 当前问题：弹层悬浮球和侧栏已经能手动标记看过，但从列表逐条筛选时仍需额外一次操作。
- 用户可见结果：开关开启后，点击可识别公司的职位条目即产生与悬浮球“标记已查看”相同的已查看记录；关闭时保持现有行为。

## 范围

### 包含

- 在侧栏“当前页面”区新增独立开关“点击职位条目即记看过”，默认关闭，本机保存。
- 开关开启后，用户点击搜索结果中的职位条目，若该条目内只有一个可靠公司链接，则记录该公司已查看。
- 记录只写“已查看”，不写 `contactedAt` 或 `contactSource`，首次记录时间与既有记录格式保持不变。
- 成功记录后复用本次查看状态，使绿色“本次已记录”和当前可用撤销路径尽量与悬浮球手动标记一致。
- 开关状态使用独立本机设置键，不进入公司记录、CSV 或话术内容。
- 写入前复核活动标签页、BOSS 页面、当前页面/公司身份、来源和文档状态；不修改 BOSS 业务 DOM，不自动点击或发送沟通。

### 不包含

- 不记录匿名职位、无法唯一定位公司、同一卡片存在多个冲突公司链接的条目，不按公司名称猜测。
- 不在开关关闭时改变现有列表只查重行为；仍不批量记录列表中所有公司。
- 不新增“已沟通”，不读取聊天正文，不改变公司页自动记录、悬浮球、侧栏手动按钮或 CSV 字段。
- 不新增上传、云同步、权限或外部服务。

## 用户流程

1. 用户在侧栏打开“点击职位条目即记看过”开关，本机记住选择。
2. 返回搜索结果列表，点击某条职位条目。
3. 条目对应公司可唯一识别时，后台记录该公司已查看，侧栏/悬浮状态同步为本次已记录。
4. 条目无法识别公司时跳过记录，用户可继续浏览，不弹出阻断提示。
5. 用户关闭开关后，点击条目恢复原有“仅展开/打开职位，不自动记录”的行为。

## 交互说明

- 入口：侧栏“当前页面”区的本机开关。
- 默认状态：关闭，避免升级后无感改变既有记录行为。
- 操作反馈：开关保存失败时回退并就地提示；点击无法识别公司的条目时静默跳过，不做误导性成功提示。
- 重复点击：同一公司只保留首次已查看时间，后续点击不覆盖既有数据。

## 数据与安全边界

- 读取：用户点击的搜索结果卡片中已存在的公司链接和名称证据；本机开关值。
- 写入：既有 `company:boss:<id>` 已查看记录；独立本机开关键 `settings:list-click-view`。
- 不得做：不利用名称模糊匹配代替公司键，不从无关卡片或相邻详情取公司，不把沟通状态误写入已查看记录。
- 原系统影响：仅监听点击和读取现有 DOM，不修改 BOSS 节点、不阻止点击、不改变导航。

## 失败与边界情况

- 匿名公司、`javascript:;` 公司链接、多公司冲突或列表尚未加载完成：不记录。
- 点击后页面/公司发生变化：后台复核失败则不写入，并允许用户继续浏览。
- 开关保存失败：视觉状态恢复原值并显示可重试提示。
- 记录保存失败：不显示成功；可由既有侧栏/悬浮球入口再次明确标记。

## 验收标准

1. 开关默认关闭；关闭时点击搜索结果条目不会新增记录。
2. 开启并点击含唯一公司链接的条目后，只新增/保留已查看记录，不写沟通字段。
3. 同一公司重复点击不改变首次已查看时间；公司页自动记录和已有数据保持兼容。
4. 匿名、冲突、无法识别、非前台或页面已切换时不写入，不按名称猜测。
5. 开关重开侧栏后保持原选择；不进入公司 CSV，不新增权限或业务 DOM 写入。

## 开发执行建议

- 复杂度：中等；主要风险是点击、内嵌详情更新与后台身份复核之间的时序，以及避免由名称猜测造成误记。
- 推荐模型：GPT-6.1 Sol / High；涉及点击时序、消息校验、持久化与回归测试，High 可降低误记和返工风险。
- 备选：GPT-6.1 Sol / Medium；实现速度更快，但需更谨慎复核异步选择和身份变化。
- 模型推荐仅供参考，实际沿用用户手动选择，不自动切换。
