# 本次与全部岗位导出

- Status: awaiting_acceptance
- Priority: medium
- Requirement revision: r1
- Target version: 0.22.0
- Confirmed date: 2026-11-06
- Development started date: 2026-11-06
- Completed date: not completed
- 来源：用户要求在侧栏并列“导出本次采集”和“导出所有岗位”，并确认“本次”包含当前会话成功采集或更新的岗位。

## 目标与用户价值

- 用户目标：完成一轮采集后，直接导出这一轮处理的岗位；需要回顾全部资料时仍可导出完整快照。
- 当前问题：只有一个“导出岗位”，始终导出全部岗位，无法区分本轮采集内容和历史积累。
- 用户可见结果：侧栏出现“导出本次（N）”和“导出全部（M）”两个并列入口，文件名也区分本次与全部。

## 范围

### 包含

- 当前采集会话记录成功采集或更新的岗位键，按岗位去重；同一岗位重复更新只算一个岗位。
- “导出本次”只包含当前会话成功采集或更新的岗位；失败岗位和未被本次触碰的历史岗位不包含。
- “导出全部”保持原行为，包含当前本机保留的全部有效岗位。
- 暂停后的当前会话仍可导出本次；开始新会话后本次清单清空，全部导出不受影响。
- 两个导出沿用相同 CSV 字段和排序：最近采集时间倒序，时间相同按岗位标识。
- 文件名分别包含“本次”或“全部”，避免两个文件混淆。
- 侧栏按钮显示对应数量；本次无成功岗位时禁用，全部无岗位时禁用。
- 会话岗位键只存于`chrome.storage.session`，不进入岗位记录、公司记录、CSV额外字段或看板。

### 不包含

- 不实现“上次导出之后新增”的增量模式。
- 不删除岗位、不清空历史、不改变薪资待重采状态。
- 不新增权限、网络请求、外部服务或岗位资料字段。
- 不为两个范围生成同一个文件或额外 sheet；仍各自生成独立 CSV。

## 用户流程

1. 用户开始采集并成功采集或更新若干岗位。
2. 侧栏显示“导出本次（N）”和“导出全部（M）”。
3. 点击“导出本次”，生成仅含本会话岗位的 CSV；点击“导出全部”，生成全部岗位 CSV。
4. 暂停后可继续导出本次；重新开始采集后本次清单从零开始，全部仍保留。

## 数据与安全边界

- 读取：当前会话`job-capture:<tabId>`中的成功岗位键；当前全部有效`job:`记录。
- 写入：仅会话中的岗位键列表；不新增本机岗位字段或长期导出历史。
- 消息：`JOBS_EXPORT`仍只接受本扩展panel来源；本次导出复核当前活动标签和会话标签一致，页面切换后拒绝旧范围。
- 不得做：不把本次清单上传、不同步、不写入公司记录，不改变既有CSV列和公式防护。

## 失败与边界情况

- 本次没有成功岗位：按钮禁用；即使请求到达后台也返回0，不生成空文件。
- 当前标签已切换或会话已关闭：拒绝本次导出并提示重新打开侧栏。
- 暂停：本次清单保留；新会话：本次清空。
- 全部没有岗位：全部导出禁用。

## 验收标准

1. 采集本次若干个岗位后，“导出本次”只包含这些成功采集/更新的岗位，失败岗位不出现。
2. 本机另有一个未被本次触碰的历史岗位时，全部导出包含它，本次导出不包含。
3. 同一岗位在本次重复更新只出现一行，首次采集时间保留，最近采集时间更新。
4. 暂停后仍可导出本次；开始新会话后本次为0，全部数据不变。
5. 两个 CSV 字段和排序一致，文件名区分“本次/全部”；不新增权限或岗位字段。

- 复杂度：中等；主要风险是“本次”边界、暂停/新会话重置和窄侧栏两个按钮布局。
