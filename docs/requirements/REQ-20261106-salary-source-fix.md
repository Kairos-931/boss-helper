- Status: awaiting_acceptance

- 用户反馈：原插件能采到薪资，新版采集不正确/没有取得薪资。

## 根因与验证缺口

本地保存的真实列表HTML共16个薪资节点（含当前详情）均含Unicode私用区字符；当前parser直接使用textContent，输出的salary仍有U+E032等字符，不是普通可导出数字。页面依靠字体把这些字符显示为数字，不能按字符值猜实际薪资。

原插件监听BOSS职位详情接口并再次请求取得JSON；0.19.0改为DOM字段提取，未继承原接口数据路径。此前只验证薪资字段非空，合成fixture使用明文数字，没有验证真实样本的可读性。这是本轮开发与验收遗漏，不归因于Excel格式。

已检查保存样本，没有可用的薪资结构化元数据或明文替代属性。用户当前具体岗位/导出尚未取得，因此以上证明当前实现确有此缺陷，不把所有缺失薪资情况都归为同一种线上原因。

## 建议修复范围

1. 薪资恢复优先来自原工具使用的BOSS职位详情接口业务JSON；HTML负责提供可回访的岗位标识/链接与当前详情复核。其他既有岗位字段保留，若采用接口补充也只保存明确业务字段，不把整个响应无选择长期存储。
2. 新增`webRequest`权限，仅限已有BOSS域名，监听固定`/wapi/zpgeek/job/detail.json`请求。用户开启本标签页采集后，才按原工具方式对真实出现的该详情请求进行受控读取；暂停/其他标签页不触发资料读取。需要同时将当前connect-src none与静态禁网络约束改为只允许该后台采集路径；域名范围不扩大。
3. webRequest完成事件不提供响应正文，不能将其描述为零额外请求的原响应保存。若采用原程序的再次请求，必须有次数限制、请求去重、忽略扩展自身请求、防循环、失败反馈，并核对当前标签/会话/文档、接口岗位标识与HTML具体岗位完全对应。不能用500ms间隔或“最近点击”猜岗位。
4. 接口实际结构、字段名称及公开岗位标识关联以获得的样本核实，不假定未读到的字段一定存在。JSON业务错误、缺字段、未知薪资类型、私用区编码不能报作正确薪资；面议作为明确文本保留，金额/单位/薪数不猜测。
5. 既有错误薪资不能按编码猜改；修复后重新打开同一岗位、取得可靠数据时按原岗位键更新，保留首次采集时间；默认不扫描或批量请求历史岗位、不清空现有记录，不改原公司已查看/已沟通与话术。
6. 只在本机处理；不读取聊天正文，不保存Cookie、认证令牌、带认证参数的完整请求URL或完整敏感日志，不绕过平台验证。

## 字段核对与实现

- 2026-11-06只读取得BOSS公开页面及其静态JS，无登录凭据、无真实详情API调用：[岗位页面模块](https://static.zhipin.com/zhipin-geek-spa/web/v6807/static/js/job~1.bc58efa8.js)读取响应zpData，[详情组件](https://static.zhipin.com/zhipin-geek-spa/web/v6807/static/js/7201.3aacd3dd.js)明确使用jobInfo.encryptId和jobInfo.salaryDesc，显示前调用mixFont。以此核对字段；真实登录响应与当前用户端仍须验收，不将合成响应称为真实API样本。
- 新模块严格固定端点/GET XHR/原站来源、开启会话/原请求时间/前台/文档约束，30秒内等待正确读取器、一次受控读取、8秒超时及防自触发；暂停/新请求/导航/关闭可中止。API与HTML确切岗位键不相等时等待，不保存未显示岗位。
- 仅保存经校验的薪资与salarySource，接口优先，无接口时可用明文DOM回退。范围、小数、单位、明确薪数及面议保留；未知/PUA/错误结构不标成功。旧坏薪资只在导出标记和状态提醒，不修改原值；可靠重采同岗位后保留首次时间更新。CSV增加薪资来源，其他公司规则和话术独立。
