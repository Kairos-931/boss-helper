## 目标与用户价值

- 用户目标：在数据看板直接看到累计采集了多少个去重岗位；侧栏按“先看当前页面、再处理话术和岗位采集”的顺序更顺手。
- 目标用户：在电脑 Chrome 上使用 BOSS 直聘岗位采集和公司记录看板的本项目用户。
- 当前问题：看板只统计公司记录，看不到岗位采集总量；岗位采集位于话术上方，与常用操作顺序不一致。
- 用户可见结果：看板新增“已采集岗位”指标；侧栏“岗位采集”移动到“打招呼话术”下方、“我的记录”上方。

## 范围

### 包含

- 看板指标区新增“已采集岗位”，数值为当前本机有效 `job:` 去重记录总数，与侧栏“累计 N 个岗位”口径一致。
- 看板通过独立只读 `JOBS_SUMMARY` 消息取得总数；后台只返回计数，不返回岗位名称、链接、描述或其他岗位明细。
- 岗位统计读取失败时显示“—”和“统计读取失败，重开看板”，不得伪装成 0；公司记录读取成功时仍正常展示公司数据。
- 看板监听公司记录和岗位记录的本机变化，任一变化后刷新当前统计。
- 侧栏“岗位采集”整块移动到“打招呼话术”下方；采集、暂停、重试、导出和提示文案不变。

### 不包含

- 不在看板展示岗位清单、筛选、比较、公司关联或薪资分布。
- 不改变岗位采集写入规则、去重规则、CSV 字段、公司记录格式、话术或悬浮球。
- 不新增权限、网络请求、外部服务、云同步或数据上传。

## 用户流程

1. 用户从侧栏点击“打开数据看板”。
2. 看板在“已记录公司”后显示“已采集岗位”及去重总数。
3. 用户继续采集岗位，返回或刷新看板时数字随本机岗位记录更新。
4. 岗位统计暂时读取失败时，用户仍能查看公司看板，并看到该指标失败提示。
5. 用户在侧栏按“当前页面 → 打招呼话术 → 岗位采集 → 我的记录”的顺序操作。

## 数据与安全边界

- 读取：本机 `job:` 有效记录总数；既有公司记录读取保持不变。
- 写入：本需求不新增任何存储写入。
- 消息授权：`JOBS_SUMMARY` 只接受本扩展精确 `dashboard.html` 页面；不授予看板岗位明细、采集开始/暂停/状态或导出权限。
- 不得做：不把岗位数写入公司记录、CSV 或话术；不从看板触发采集、导出或网络请求。

## 失败与边界情况

- 没有岗位记录：显示 0，不显示空状态错误。
- 岗位记录损坏或后台读取失败：显示“—”，公司数据继续展示，并提示重新打开看板。
- 公司记录读取失败：沿用原看板错误提示，不呈现虚假的公司零记录。
- 公司记录与岗位统计其中一项失败：另一项已成功的数据保持可用。

## 验收标准

1. 看板显示“已采集岗位”，数值等于侧栏累计去重岗位数；同一岗位重复采集更新不增加数字。
2. 没有岗位时显示 0；读取失败显示“—”和可行动的提示，不显示假 0。
3. 岗位统计失败不影响公司指标、趋势、分布和清单的正常展示。
4. 侧栏“岗位采集”位于“打招呼话术”下方、“我的记录”上方，采集和导出行为保持不变。
5. 不新增权限、网络请求、岗位明细读取或任何存储写入。

## 开发执行建议

- 复杂度：低；主要风险是看板消息授权和统计读取失败时不要覆盖公司数据。
- 推荐模型：GPT-6.1 Sol / Low；改动集中在只读计数、布局顺序和少量回归检查。
- 模型推荐仅供参考，实际沿用用户手动选择，不自动切换。
