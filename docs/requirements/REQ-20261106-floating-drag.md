# 悬浮球拖拽与位置记忆

- Status: awaiting_acceptance
- Priority: medium
- Requirement revision: r1
- Target version: 0.17.0
- Confirmed date: 2026-11-06
- Development started date: 2026-11-06
- Completed date: local implementation 2026-11-06; actual acceptance pending

## 目标与用户价值

- 用户目标：把悬浮球放到自己习惯的位置，避免固定入口遮挡当前页面内容。
- 目标用户：在电脑 Chrome 上使用 BOSS 直聘悬浮球的本项目用户。
- 当前问题：悬浮球只能固定在右侧，不能按页面内容和个人习惯移动。
- 用户可见结果：按住“助”字球拖到视口内任意位置，松手后记住位置；悬浮条围绕球展开，不把球挤走。

## 已批准范围

- 悬浮球使用 `42×42px` 固定锚点，位置以球左上角的视口坐标保存。
- 按住悬浮球拖动，移动超过约 `5px` 才视为拖拽；松手后保存位置。
- 位置限制在可视区内；窗口尺寸变化后重新限制，不保存屏幕外坐标。
- 悬浮条根据球所在左右半屏自动显示在球的左侧或右侧，并在垂直方向避开视口上下边缘。
- 拖拽结束后抑制随后的单击/双击事件，不误触“标记已查看”、撤销或打开侧栏；未发生移动的普通点击保持原逻辑。
- 位置只保存在本机独立键 `floating-position`，不进入公司记录、CSV、话术或沟通字段。
- 不新增权限、不读取聊天正文、不修改 BOSS 业务 DOM，不改变既有公司身份和记录写入规则。

## 不包含

- 不把拖动位置同步到云端或其他设备。
- 不改变悬浮球的颜色、单击、双击、撤销、侧栏收起或提示音规则。
- 不为拖动位置新增公司记录字段或 CSV 列。

## 用户流程

1. 页面出现“助”字悬浮球，默认仍在右侧常用位置。
2. 用户按住球拖动，球跟随指针移动；悬浮条在拖动期间收起。
3. 用户松手，球停在当前可视位置，并保存到本机。
4. 再次打开页面或重新加载扩展后，球回到上次位置；窗口变窄/变高时自动调整到可视区内。
5. 用户悬停球时，悬浮条根据剩余空间显示在球的左侧或右侧。

## 失败与边界

- 位置保存失败：保留当前拖动位置，悬浮条显示“位置未保存：…”并允许下次拖动重试，不显示成功。
- 位置读取失败：使用默认右侧位置，不阻断悬浮球和记录功能。
- 连续拖动：位置保存串行发送，新位置不会被旧保存结果覆盖。
- 页面切换或扩展重载：位置仍是本机偏好，不影响当前公司身份和记录。

## 验收标准

1. 按住悬浮球移动超过约 `5px` 后松手，球停在指针释放位置，并写入本机 `floating-position`。
2. 拖到视口边缘时不会移出可视区；窗口尺寸变化后仍完整可见。
3. 拖拽后的 click/dblclick 不触发标记已查看、撤销或打开侧栏；未移动的单击和双击保持原有行为。
4. 悬浮条在球位于左半屏时向右展开、位于右半屏时向左展开，展开/收起不移动球。
5. 保存失败不伪装成功，当前位置保留并显示错误；读取失败使用默认位置。
6. 不新增权限、公司记录字段、CSV 列或 BOSS 业务 DOM 写入。
