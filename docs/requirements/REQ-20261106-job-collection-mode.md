## 1. 结论与产品定位

建议在现有助手增加独立“岗位采集”入口，保留原浏览辅助。首版负责收集资料、补齐岗位定位信息和表格导出；集中筛选比较在 Excel 中完成。不以本次需求建立内置岗位库、候选管理或比较页面。

用户的实际任务分为两段：先在 BOSS 上发现机会并由助手保存，再导出到 Excel 筛选和比较，选中后通过岗位链接回到 BOSS。收集不是筛选结论，也不是投递或沟通行为。

“另一种模式”首先表达为另一条工作流程，无需为了这一流程先建两个完整工作区。建议提供独立开始/暂停和导出，收集期间继续使用原公司提醒；采集运行状态与原公司行为记录分别管理。

本次沿用原公司查看与沟通规则，采集功能独立叠加；不把“研究时完全不产生公司浏览记录”列为待确认需求。用户未来明确提出行为变更时再单独处理。

## 3. 旧项目实际实现了什么

| 能力 | 实际行为 | 产品价值 | 当前缺口 |
| --- | --- | --- | --- |
| 主动启动 | 弹窗发 START，后台内存变量置为开启 | 用户决定开始收集 | 没有暂停/结束入口，也没有可信的运行状态展示 |
| 发现详情请求 | 监听固定职位详情接口完成事件 | 利用浏览过程中出现的岗位 | 没有把请求与当前选中的岗位可靠绑定 |
| 过滤请求 | 全局比较 500ms 间隔 | 尝试排除预加载 | 时间间隔不能证明用户点击，快点可能漏收，慢预加载可能混入 |
| 获得数据 | 请求完成后用 fetch 再请求同一 URL，携带登录态 | 取得 JSON 资料 | 不是直接保存原响应；重复请求的成功、身份及业务状态未验证 |
| 本机保存 | JSON 整体追加到 chrome.storage.local.jobs 数组 | 留存资料 | 无岗位去重、字段标准化、来源时间、版本变化与串行保存保护 |
| 数量展示 | 打开弹窗时读取数组长度 | 知道累计保存多少条 | 是返回对象条数，不能解释为唯一岗位数或有效岗位数；打开后不实时更新 |
| 导出 | 把全部数组下载为 JSON | 交给外部工具处理 | 无可读表格、选择导出、导入恢复或结果核实 |
| 清空 | 确认后把 jobs 置为空数组 | 清理采集结果 | 全量操作；不停止收集，不能代替结束本次任务 |

用户实用反馈补充：旧工具已能采到岗位信息，主要缺口之一是没有随资料保存具体岗位 ID 和直达链接，导致筛选后还需搜索公司、重新定位岗位。新模式应将“选中后能直接回到该岗位”列为基本闭环。

明确未实现：自动翻页、自动打开职位、批量遍历、搜索任务、定时运行、岗位列表查看、筛选、对比、收藏、AI 分析、自动沟通/投递、云同步。不能把“捕获接口”描述成这些能力已经存在。

### 可靠性问题如何影响产品

1. 启动状态只在后台全局变量中，后台被回收后会恢复为关闭，界面又缺少状态核对，用户可能以为一直在收集。
2. 500ms 是全局节流，不区分标签页、岗位和用户行为。需要改成“本次会话、允许的页面、确切岗位、保存成功”四件事均可确认。
3. 保存前不检查 HTTP/业务成功标识和必要字段，报错 JSON 可能进入数组；异常被吞掉，用户不知道漏收。
4. 数组读改写没有队列，若保存操作重叠，存在后写覆盖前写的风险；这是静态代码风险，未在真实端复现。
5. 没有排除扩展自身请求的显式条件，是否再次触发监听、产生重复请求链需专项核实，不能当作已确认运行故障。
6. 点击“启动”后的提示没有等待后台确认；导出提示只说明触发下载，不能证明文件已落盘。

这些发现属于外部原型的评估，不登记为现有公司助手已发生的缺陷，也不以本次讨论授权修复外部项目。

浏览器行为参考：[Chrome 后台生命周期](https://developer.chrome.com/docs/extensions/develop/concepts/service-workers/lifecycle)说明后台退出会丢失全局变量；[webRequest 官方参考](https://developer.chrome.com/docs/extensions/reference/api/webRequest#event-onCompleted)说明完成事件的参数。产品上应保留“保存浏览中岗位资料”的目标，采集方式需重新验证，不绑定旧代码。

## 6. 数据对象拆分：首版三类信息，筛选结论留在 Excel

### 公司行为记录：我与哪家公司发生过什么

沿用现有公司查看与沟通语义。所有历史时间和手动状态保持，不能由收集资料批量补记。现有 CSV、公司清单和看板继续只统计这些记录。

### 岗位资料：我保存了哪个机会

独立保存岗位身份、链接、职位名、可靠的公司关联、岗位字段和快照时间。同公司不同岗位各一条；同一岗位多次保存更新资料，不增加唯一岗位数。Excel 中的个人结论由用户维护，本项目首版不保存或回写这些结论。

#### 已确认补充：岗位定位信息与内容一同保存

- 用户目标：在导出表中通过岗位链接直接进入当时保存的具体岗位，无需先搜索公司。不以公司页面冒充岗位链接；失效不等于可以保证恢复原岗位。
- 来源分工建议：已验证可采集的岗位内容继续作为内容来源候选；页面 HTML 的确切职位链接、被点击卡片及对应详情补充岗位公开标识和链接。数据由多个可靠来源组成，不要求所有字段来自同一个接口。
- 优先读取页面实际存在的 `/job_detail/...html` 职位链接；独立职位页可核对地址栏链接，列表内嵌详情不可直接保存列表 URL 当作岗位链接。
- 详情里的 `data-job-id`、`data-jobid`、`data-encrypt-job-id` 可作关联证据候选。现有 `core/identity.js`、`core/parser.js` 已有链接识别、这些属性的读取及卡片/详情匹配逻辑；这里只能证明有可复用基础，不能证明任意属性值都是同一类型的公开标识或可以直接拼成有效 URL。
- 岗位公开标识、接口内部 ID 与本机资料 ID 分开解释；如页面公开标识足以可靠去重和定位，不必为取得内部数字 ID 增加额外流程。
- 关键验证：接口内容与页面链接必须属于同一个确切岗位。尤其快速切换 A/B 岗位、响应乱序或预加载时，不能只因“最近一次点击/最近一次响应”就合并；需验证可用的共同标识或采用与当前确切详情绑定的内容来源。若无法证明对应，不生成看似完整的关联记录。
- 产品建议：缺链接的资料明确显示“缺少岗位链接”，与可直接回访的完整资料分开；不拿公司链接替代，不静默合并同名岗位。暂存及计数规则在最终规格中确认。
- 导出应保留岗位标识与直达链接，筛选与比较后的“打开原岗位”始终使用这条岗位链接；历史无链接资料不能仅凭公司名与职位名自动补造身份。

候选字段分组：

| 分组 | 候选内容 | 产品要求 |
| --- | --- | --- |
| 可回溯信息 | 岗位身份、原链接、职位名、来源页面、收集/更新日期 | 字段与身份要验证；无法可靠确定岗位身份时不合并到既有岗位 |
| 初筛条件 | 薪资原文与可比较范围、薪资月数、城市/区域、经验、学历 | 无法统一就保留原文和未知；不把面议当零，不假定“13薪”等已确认收入 |
| 岗位内容 | 职责、要求、技能、职位标签 | 保存岗位业务内容，不读取聊天正文 |
| 公司背景 | 公司键、名称、规模/行业等可核实字段 | 公司名称不足以建立关联；接口字段与现有公司键关系需证明 |
| 工作制度 | 岗位原文与来源、公司已记录制度 | 冲突并列展示；没有匹配值不能自动写成双休 |
| 资料质量 | 缺失字段、保存时间、来源、是否成功关联公司 | 未知可见；只展示采集样本能够支持的字段 |

不建议把完整原始 JSON 永久当主数据：未知字段可能包含无关个人信息，格式也不稳定。先明确需要保存的职位业务字段；原始调试资料若确需保留，另定范围和清理规则。首版不需要招聘者私人联系方式、聊天、Cookie 或令牌。

### 筛选结论：首版在 Excel 中管理，产品内仅留后续设想

首版不新增“待筛选/候选”、备注、评分或淘汰理由数据，不读取或回写用户 Excel 文件。用户在 Excel 中自由筛选、比较、标记与记录判断；新导出是独立数据文件，不覆盖用户已经编辑的工作簿。重复导出时通过稳定岗位标识辅助用户识别同一岗位，不预设自动合并或双向同步。

未来若真实使用暴露 Excel 难以解决的问题，再单独讨论内置筛选结论；这些为后续设想，不构成本轮执行队列。此前用户已取消公司级“无合适岗位”标记，不能借新模式恢复。

### 收集会话：这一次收集是否在运行

记录本次运行范围和状态，提供新增、已收过/更新、失败的分开计数。“本次新增”与“累计采集岗位数”分开。清空数据不等于停止会话，暂停不删除已有岗位。

公司与岗位是一对多；未知公司也可以有岗位资料，但不允许借岗位名称猜公司身份。收集公司背景元数据不等于创建“已查看公司”行为记录。

## 7. 哪些能力结合，哪些能力隔离

| 能力 | 结合方式 | 隔离规则 |
| --- | --- | --- |
| 公司身份 | 复用现有唯一键和冲突检查 | 不按名称合并；接口 ID 需验证映射 |
| 当前职位上下文 | 复用现有岗位键、详情与卡片关联证据 | 不把任意详情请求当作当前打开岗位 |
| 已看过公司 | 采集时可展示，导出可附带公司查看背景，具体列待定 | 不把岗位入库当公司查看事件 |
| 已沟通公司 | 可导出“公司已沟通”供 Excel 筛选，具体列待定 | 不显示成“该岗位已沟通”，不自动排除该公司其他岗位 |
| 休息制度 | 作为筛选参考，并显示证据来源 | 岗位与公司不互相静默覆盖 |
| 悬浮球与声音 | 沿用原公司历史提示，可加低干扰收集反馈 | 已收集不复用红球/铃声，不更换现有单击与双击语义 |
| 侧栏 | 浏览辅助保留；收集时提供简洁的开始/暂停、计数与导出 | 首版不增加岗位筛选器或比较表 |
| 全屏看板 | 原公司看板继续使用；岗位库仅作为后续设想 | 首版不扩展岗位分析或候选统计 |
| 话术 | 选中候选后复用现有复制流程 | 不自动把岗位正文写进持久话术框，不自动发送 |
| 设置 | 共用设置入口 | 收集开关独立；不修改列表点击记录、声音及复制后收起偏好 |
| 导出 | 一处入口可选公司记录或岗位资料 | 公司 CSV 字段兼容；岗位格式另定义 |
| 删除与撤销 | 用一致的反馈与恢复设计，具体采集数据清理入口待定 | 清理岗位不删公司；撤销公司查看不删岗位；取消沟通不改变 Excel 中个人结论 |
| 存储与权限 | 一个助手管理本机资料，数据按职责分区 | 保存/导出/分析失败不能阻断原公司记录；权限和数据范围另确认 |

删除公司记录后，岗位可以继续显示公司名称和原链接，但“已看过/已沟通”标记应随现有行为记录消失，不因岗位关联重新创建记录。

## 8. 最容易互相干扰的动作表

| 用户动作 | 岗位资料变化 | 公司行为记录变化 |
| --- | --- | --- |
| 开始收集 | 建立本次会话 | 无 |
| 收集当前岗位成功 | 新增岗位或更新快照 | 收集动作自身无写入 |
| 同时开启原“点击职位条目即记看过”并点击条目 | 满足收集条件则保存岗位 | 由原开关按现有规则记录公司查看 |
| 关闭原列表点击开关后打开职位 | 满足收集条件则保存岗位 | 不因收集自动记查看；保留手动标记入口 |
| 进入公司详情页 | 不因此批量保存公司的岗位 | 原公司页自动记录继续生效 |
| 在 BOSS 上真实发送消息 | 不据此判定具体岗位处理状态 | 按现有可靠证据写公司沟通 |
| 在 Excel 查看导出资料 | 扩展存储不变 | 无 |
| 在 Excel 筛选、标记候选或备注 | 仅修改用户工作簿，首版不回写助手 | 无 |
| 清理采集资料（入口及范围待定） | 仅处理助手保存的岗位资料，不操作用户 Excel 文件 | 不删除查看、沟通或话术 |
| 撤销公司记录 | 岗位快照保留 | 沿用原撤销规则，关联展示重新计算 |
| 查看原公司记录或关闭侧栏 | 不因界面切换自动停止会话，运行标识的保留方式待定 | 无额外变化 |
| 暂停收集 | 停止接纳新的收集；暂停前已确认接纳的保存可完成并反馈 | 原浏览与沟通规则继续 |

这里的“互不干扰”是因果分离：收集动作自身不写行为记录；用户仍进入公司页或启用原点击记录时，旧规则正常产生记录。这一结合边界已经明确，不再重复询问是否沿用。

## 9. 建议的用户流程与界面

1. 用户打开 BOSS 列表，在助手点击“开始收集”。默认仅当前标签页，显示“收集中 · 本次新增 0”。
2. 用户照常打开感兴趣的职位。只有详情与本次打开岗位可靠对应、资料有效并保存成功才增加计数；预加载和其他未加入的标签页不计入。
3. 原公司历史提醒继续帮助判断；“该公司以前沟通过”和“这个岗位以前收过”分开显示。
4. 收集后导出 Excel 可直接打开的岗位表格；格式由实现时选择，默认导出范围及重复导出规则在定稿时明确。
5. 用户在 Excel 中筛选、排序、比较并记录候选与备注，助手不建立对应界面或同步这些结论。
6. 在 Excel 点击岗位链接回到 BOSS 原职位，确认当前招聘信息并人工沟通；原话术和沟通记录继续使用。

界面分工：悬浮条保留当前上下文和低干扰反馈；侧栏承载简洁采集控制及导出；Excel 承载筛选和比较。继续使用本扩展入口，不新增本地服务地址。

默认会话建议在关掉收集标签页或重启浏览器后结束；后台短暂休眠不应悄悄取消。查看其他界面不等于结束收集，也不应看不到“仍在收集”。这些为建议，尚未确认运行规则。

## 11. 分阶段建议

### 阶段 0：最小资料可行性核对

用户手动提供少量去敏样本，核对岗位身份、可用字段、公司键映射、不同职位入口及失败情况；不为了补数据自动调用登录接口或启动桌面控制。若已有可用导出 JSON，可优先检查，当前目录未发现业务样本。

输出应是“确实可取得的字段与来源”及产品取舍。历史接口采集成功已有用户确认，重点核对当前资料字段，并验证 HTML 补充的岗位标识/链接如何与内容对应。比较“接口内容加页面定位信息”和“已加载详情直接取内容”两条路径，再定读取方式和权限；不预设旧采集方式必须全部重做。

### 阶段 1：能放心收，能导出到 Excel

建议范围：独立开始/暂停、当前标签页会话、明确打开的详情、岗位身份去重、最小标准字段与快照、保存状态、原岗位链接及 Excel 可用的表格导出；与现有公司行为记录的关联展示/导出列待定稿。首版没有岗位库搜索、筛选器、候选管理或并排比较。

优先成功标准是“采集结果带准确岗位标识和链接，导出后可直接在 Excel 整理，并能从表格回到具体岗位”。首版不做自动翻页、自动投递、复杂任务调度、AI 评分或一整套招聘 CRM。

导出建议：一岗位一行、固定中文列名、标识按文本保留、字段缺失有一致表达、日期含义清楚；职位名称、公司、岗位链接、采集时间为基础，薪资/城市/经验/学历/JD 等按实际可得性确认。原始描述保留；需要拆分薪资上下限等结构化处理时再评估，不把大量复杂清洗默认塞进首版。CSV/XLSX 属于低影响实现选择，无需单独用户确认，也不扩展为操作或同步用户现有 Excel 工作簿。

### 后续设想：按 Excel 实际使用问题决定是否内置

保留内置岗位清单、筛选器、候选管理和横向比较的探索记录，均不排入首版或默认下一期。先观察 Excel 流程是否反复出现明确障碍，再决定是否值得开发，不能仅因存在技术可行性就启动。

### 阶段 3：有证据再扩展

只有在实际筛选中反复出现需求后再加批次、资料变更提醒、市场分布、岗位摘要或匹配辅助。若涉及第三方模型分析，须明确发送哪些资料、费用和授权；当前没有上传或云同步授权。

## 13. 后续验收候选

1. 同一公司两个岗位保留两条岗位资料，只关联同一公司身份；同一岗位重复收集不增加唯一岗位总数。
2. 收集关闭、其他未加入的标签页、预加载、身份冲突或无效资料不新增成功记录，且不伪装成成功。
3. 仅收集岗位不写公司查看或沟通；原列表开关与公司页自动记录仍按原规则可单独验证。
4. 无可靠公司关联的岗位可按实际证据保存和导出，并明确公司关联未知，不因名称相似合并或创建行为记录。
5. 更新岗位快照与再次导出不读取或覆盖用户在 Excel 的候选、备注等个人判断；薪资面议、字段缺失与休息制度冲突均有明确表达。
6. 暂停、界面切换、后台重启及标签页关闭后的运行状态与承诺一致，不出现“显示收集中但实际停了”。
7. 收集保存失败不损坏原公司记录、不影响原查看/沟通功能；失败有明确下一步。
8. 删除岗位、撤销公司查看、取消沟通分别只改变对应数据；不能互相触发级联删除或自动重建。
9. 公司看板仍统计公司行为记录；采集数量按唯一岗位口径，首版不增加岗位分析看板或候选统计。
10. 导出表一岗位一行、列名与内容对应、标识与链接完整，Excel 可直接打开并筛选排序；不以 CSV/XLSX 格式选择作为产品决策阻塞。
11. 同公司多个岗位分别保留正确公开标识与直达链接，从导出表可直接定位具体岗位，不能全部落到公司页或列表页。
12. 快速点击 A/B 岗位、预加载和响应乱序时，不把 A 的资料配上 B 的链接；不能可靠关联时显示资料不完整，不虚报完整采集成功。

## 14. 初版开发范围：已批准

### 范围与默认行为

1. 在原助手侧栏增加简洁的“开始采集/暂停”和数量、错误反馈及“导出岗位”入口，不新建完整岗位库或比较工作区。
2. 默认关闭；用户在当前 BOSS 标签页启动后，对当前明确显示及后续主动打开、可靠匹配的岗位详情采集，不采预加载、其他标签页或列表全部岗位。暂停不删除数据；标签页关闭、浏览器重启后会话结束，后台短暂休眠不应丢失状态。
3. 本机单独保存岗位业务资料、公开岗位标识和页面实际直达链接。按可靠岗位标识去重，重复采集更新资料及最近采集时间，保留首次采集时间；无可靠身份、内容与链接不对应时不记为完整成功，不以公司名/岗位名猜合并。
4. 原项目已采集成功的资料路径作为开发调查起点，核对与 HTML 定位证据的绑定；优先复用现有页面读取能力和既有权限。不能为尽快完成而默默丢失原工具的核心岗位资料。如必须新增接口监听、权限或扩大页面读取边界，先报告具体必要变更再处理，不以本次确认自动授权任何新权限。
5. 默认导出当前全部去重岗位资料，生成独立文件，不修改用户 Excel；先采用现有 CSV 导出基础可复用的方式，必要时选择 XLSX，不为格式另设确认。列包括：岗位标识、职位名称、公司名称、岗位链接、薪资原文、城市、经验、学历、岗位描述、首次/最近采集时间；缺失字段留空且不猜测，具体证据在技术设计中核对。
6. 有可靠公司关联时，允许在岗位导出附带“公司已查看/公司已沟通”及公司链接，明确公司口径；缺少可靠关联时状态为未知，不写成“未看过/未沟通”。不因采集创建公司行为记录，原记录规则独立继续。
7. 不包含内置筛选、候选/备注、比较、AI 分析、自动翻页/点击/发送、云同步、Excel 回写、历史采集 JSON 导入或全量清空公司记录。采集清空/复杂管理不作为隐含必做项。
