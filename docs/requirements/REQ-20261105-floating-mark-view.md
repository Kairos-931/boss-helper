# 悬浮条职位详情标记已查看

- Status: awaiting_acceptance
- Requirement revision: r2
- Target version: 0.16.0
- 来源：2026-11-05 用户要求把搜索结果页悬浮条的“标记已沟通”替换为“标记已查看”，并提供真实搜索结果页 HTML。
- 开发批准：2026-11-05 用户回复“开始”，批准已展示范围。沿用当前模型与中等推理，实际模型不自动切换；仅确定性验证，无GUI、安装、push或发布。
- r2补充批准：2026-11-05 用户回复“1”，选择“绿色本次已记录单击先展开悬浮条，条内明确点击撤销”，并保留未记录单击标记已查看、双击打开侧栏的交互。
- 页面证据：只读解析用户提供的搜索结果页 HTML，得到 `kind: detail`、`detailType: job`、`source: job-card-match`、当前公司“网易有道”，属于内嵌职位详情。

## 目标与用户价值

- 用户目标：在搜索结果里查看职位时，先用悬浮条记录“已查看”，不把尚未发生的沟通误记成“已沟通”。
- 用户可见结果：未记录的职位详情悬浮条显示“标记已查看”；点击后生成已查看记录，按钮再变为“标记已沟通”。

## 已批准范围

- 可靠识别的职位详情页（`job-card-match` / `job-company-link`）在尚未记录公司时，悬浮条主按钮显示“标记已查看”。
- 点击“标记已查看”复用既有手动查看写入链路：只创建/保留公司已查看记录，不写入 `contactedAt` 或 `contactSource`。
- 记录成功后，悬浮条显示绿色“本次已记录”，按钮在未沟通时变为“标记已沟通”；再次点击才写入沟通状态。
- 公司详情页继续显示“标记已沟通”；已沟通公司隐藏按钮；列表、简称查询和无法识别页面不显示可写按钮。
- 新增后台 `FLOAT_VIEW` 消息，仅接受 BOSS 顶级内容脚本；写入前复核前台/活动标签、职位详情来源、token、visitId、公司键和 documentId。
- 不新增权限、不读取聊天正文、不改公司记录/CSV/话术格式，也不改变公司页自动记录。

## 不包含

- 不改侧栏既有“标记已查看”入口；侧栏本来已按未记录职位显示该按钮。
- 不对列表内所有公司批量标记，不因展开职位自动记录。
- 不把“标记已查看”当作沟通；沟通仍由手动按钮、自动发出消息或公司页既有入口记录。

## 用户流程

1. 在搜索结果中展开职位，悬浮条识别到未记录公司，显示“标记已查看”。
2. 点击后生成已查看记录，悬浮条变绿并显示“本次已记录”，按钮变为“标记已沟通”。
3. 如已沟通，再点击“标记已沟通”；取消沟通后仍保留已查看记录。
4. 公司详情页保持原“标记已沟通”行为；无法识别时不提供写入。

## r2 补充：单击、双击与撤销

- 未记录职位详情：单击悬浮球执行“标记已查看”；双击打开侧栏。单击延迟约280ms判定，检测到双击后取消单击动作。
- 绿色“本次已记录”且未沟通：单击悬浮球只展开悬浮条，不直接删除；条内显示“撤销本次记录”按钮，点击后才删除当前公司记录。
- 撤销仅允许本次会话新建的绿色记录（当前访问状态为`first`或`manual`且未沟通）；60秒内其他标签页的新记录、历史记录、已沟通记录和仅因新记录窗口变绿的记录不显示撤销。
- 撤销复用既有`visits.remove`：删除公司记录并把相关标签页本次访问标为`suppressed`；职位详情可再次明确标记，公司页保持本次已撤销语义。
- 双击始终只打开侧栏，并取消待执行的单击；键盘Enter/空格仍打开侧栏，悬浮条按钮继续负责明确写入。

## 验收标准

1. 未记录的搜索结果/职位详情显示“标记已查看”，点击后记录只有已查看，没有沟通时间。
2. 记录后按钮变为“标记已沟通”，点击才写入沟通；取消沟通后仍显示本次已记录。
3. 公司详情页仍为“标记已沟通”；列表、简称查询、无法识别和已沟通状态不显示错误按钮。
4. 伪造来源、子帧、非BOSS页面、陈旧token/visitId/公司键/文档或非前台页面均不能写入。
5. 未记录单击只写已查看；绿色本次记录单击只展开，点击“撤销本次记录”才删除；双击不删除且只打开侧栏。
6. 60秒内其他标签页新记录、历史记录、已沟通记录不出现撤销或撤销被拒绝；撤销后不误报成功。
